# Contributing

Contributions should improve the toolkit’s ability to produce accurate, useful, and maintainable product-engineering context.

## Adding or changing a skill

1. Give the skill one clear responsibility.
2. Add a discriminating description with appropriate trigger language and boundaries.
3. Define the evidence it should inspect and the artifact it should produce.
4. Do not duplicate another skill’s specialist review; use the shared collaboration contract and create a handoff instead.
5. Preserve uncertainty. Never invent metrics, requirements, policies, or compliance conclusions.
6. Add or update the Codex and Claude routing references.
7. Test the skill with at least one realistic project scenario.

## Pull requests

Please include:

- The problem the change solves
- The affected skill or plugin surface
- Example request and representative output expectations
- Validation performed
- Any compatibility or scope considerations

Keep changes focused and avoid adding provider-specific integrations unless they are explicitly part of the proposal.
