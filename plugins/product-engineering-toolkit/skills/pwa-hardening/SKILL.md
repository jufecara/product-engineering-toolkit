# PWA Hardening

> Only relevant if the project actually ships a service worker / installable manifest. Skip
> entirely for projects that aren't PWAs.

## 1. Generate, don't hand-roll

- Use a build-tool PWA plugin (e.g. `vite-plugin-pwa`, Workbox CLI/webpack plugin, Next PWA
  plugin) to generate the manifest and service worker from config, rather than writing raw
  service-worker cache logic by hand — hand-written SW caching is a common source of subtle
  stale-cache bugs.

## 2. Update strategy that doesn't silently strand users

- Prefer a prompt-based update flow (`registerType: 'prompt'` or equivalent) over silent
  auto-activation of a new service worker — pair it with a visible in-app "update available"
  UI element so users control when the app reloads onto new code, instead of being served a
  half-updated app.
- Enable outdated-cache cleanup (`cleanupOutdatedCaches: true` or equivalent) so old cache
  versions don't accumulate unbounded in the user's browser storage.

## 3. Cache scope — app shell only

- The service worker cache must hold only static app-shell assets (HTML/CSS/JS/icons), never
  mutable user/application state. Persist user/session/game state in `localStorage`/IndexedDB
  instead, so a cache purge or SW update can never silently roll back or corrupt user data.

## 4. Manifest and icon completeness

- Provide both a 192×192 and a 512×512 PNG icon, plus a maskable-purpose variant, so the app
  installs correctly across Android/iOS/desktop install prompts.
- Set `display: standalone` (or `fullscreen`/`minimal-ui` as appropriate) for the native-like
  experience the manifest is meant to provide.
- Treat already-exported icon assets as a "do not touch" directory — document this explicitly in
  the project's docs so a well-intentioned refactor doesn't regenerate them; regenerating icons is
  a design/export task, not a code edit.

## 5. Verify after every PWA-config change

- After editing the PWA plugin config or manifest, run a full build and preview (not just dev
  mode — dev-mode service worker behavior can differ), then confirm in devtools that the
  service worker registers, the manifest is valid, and offline reload still works.

## Verification checklist

- [ ] Manifest and service worker are generated by a build plugin, not hand-written.
- [ ] Update flow prompts the user rather than silently swapping code underneath them.
- [ ] Outdated cache cleanup is enabled.
- [ ] No mutable user/app state is cached in the service worker; it lives in local storage.
- [ ] 192×192 + 512×512 + maskable icons all present.
- [ ] A build+preview check confirms SW registration and offline behavior after any PWA-config
      change.
